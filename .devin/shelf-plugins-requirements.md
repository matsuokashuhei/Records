# シェルフエフェクトプラグイン機構 要件チェックリスト

前提: feature/cubby-shelf-ui(PR #21)はリファレンス実装として保存済み。
本タスクは **main から作り直し**。まずプラグイン基盤のPRを作り、
3つのプラグインはそのブランチから派生させて個別PRにする。

レビュアーは該当PRの節の項目を採点すること。

## P0. プラグイン基盤(PR1: feature/shelf-plugin-framework → main)

- [ ] P0-1. プラグイン定義: 各エフェクトを「プラグイン」として登録できる
      プロトコル/型。id(安定な文字列)・表示名・有効フラグ・調整可能な
      パラメータ群を持つ
- [ ] P0-2. パラメータモデル: スライダー等で調整可能な型付きパラメータ
      (範囲・デフォルト値を含む)。今後 enum 選択等の型追加を見込める拡張性
- [ ] P0-3. 永続化: プラグインの有効/無効とパラメータ値をシェルフ単位で
      settings.json に保存。既存settings.json(キー無し)からの
      デコード互換を保つ(Codableの後方互換。新キーは省略時デフォルト)
- [ ] P0-4. レジストリ: 利用可能なプラグイン一覧を1箇所で登録・列挙できる。
      適用順はレジストリ順で決定論的
- [ ] P0-5. 適用ポイント: レコードセルのジャケット描画に対し、有効な
      プラグインが合成される仕組み。少なくとも以下のフックを持つ:
      (a) ジャケット本体への修飾(変形・回転等)
      (b) ジャケットへのオーバーレイ重畳
      (c) セル単位の装飾(影・光等)
      プラグインは必要なフックだけ実装すればよい
- [ ] P0-6. 設定画面: SettingsViewにプラグインセクションを追加。
      各プラグイン=選択(トグル)可能・有効時にパラメータ調整UI(スライダー等)
      を表示。変更はフォーカス中シェルフへ即時反映(既存のShelfPickersと
      同じ@ObservedObjectパターン)
- [ ] P0-7. 登録ゼロでも破綻しない: プラグイン未登録の状態で基盤だけが
      存在してもよい(セクション非表示等)。ビルド・既存動作に影響なし
- [ ] P0-8. 将来の棚レベルプラグイン(木枠・区画・ヴィネット等)を見据え、
      ジャケット以外のフック追加が可能な構造(本PRで実装は不要、
      拡張可能な設計であること)

## P1. プラグイン「奥行き感(後傾)」(PR2: feature/plugin-lean-depth → framework)

- [ ] P1-1. ジャケットが背板に後ろへ倒れている表現。
      rotation3DEffect(x軸, anchor .bottom)または上辺を狭める擬似パースで実現
- [ ] P1-2. 調整可能パラメータ: 「立てかけ具合」0-50%(step 2.5)の
      単一スライダー。棚の奥行きの何%の位置までジャケット上辺が
      届くかを指定し、内部で角度=asin(lean%×sin15°)を逆算する
      (パースは0.7固定)。settings.jsonに永続化
- [ ] P1-3. 無効時は元の平面表示と完全に同じ見た目・レイアウト
- [ ] P1-4. タップ/ドラッグ等のヒット領域が壊れない(修飾後もセルの
      インタラクションが機能する)

## P2. プラグイン「スリーブ光沢」(PR3: feature/plugin-sleeve-gloss → framework)

- [ ] P2-1. 透明ビニール袋に入ったレコードのような、斜めの淡い
      ハイライト帯をジャケットに重ねる
- [ ] P2-2. 調整可能パラメータは「照明」のメタファーで直感的に:
      照明の位置(ジャケット周囲3x3のグリッドピッカー、正面=中央の
      淡い光沢)、照明の強さ(不透明度スライダー)、照明の色味
      (電球色/温白色/昼白色/昼光色の4択)。帯の幅は内部定数で固定
- [ ] P2-3. 無効時はオーバーレイ完全非表示(残像・レイアウト影響なし)
- [ ] P2-4. 光の当たり方をリアルに: 棚面を鏡とみなし視点(棚正面
      中央)と高架の点光源から鏡面反射点Sを幾何計算し、光沢帯は
      セルごとに「セル中心→S」の向きに引く(光源側の面に局所的に
      出る)。強度は点光源までの3D距離の逆二乗で減衰(最近傍セル
      =フル強度に正規化)。さらにセルごとの決定論的疑似傾き
      (±5°)で反射位置をずらし、強度も0.85〜1.0でバラつかせる

## P3. プラグイン「上からの光源」(PR4: feature/plugin-top-light → framework)

- [ ] P3-1. ジャケット/セルの影・エッジ明暗を「上方向の光」で統一する
      表現(例: ジャケットの下向き投影、上辺の受光ハイライト、
      セル上部の柔らかい照光等)
- [ ] P3-2. 調整可能パラメータ: 影の強さ(不透明度・ぼかし等)、
      ハイライト強度 等
- [ ] P3-3. 既存のセル影(rounded rectの固定shadow)との関係を整理する
      (有効時はプラグイン側の光源表現に統一、無効時は従来通り)

## P4. プラグイン「色褪せ(日焼け褪色)」id: sun-fade

対象ファイル: Records/SunFadePlugin.swift

- [ ] P4-1. transformJacket で日焼け褪色を表現する。実物観測(70枚調査)
      の典型パターンは「彩度低下+赤/マゼンタへのシフト+コントラスト低下
      (薄い霞がかった感じ)」であり、これを再現すること
- [ ] P4-2. パラメータ(定義済み・変更しない):
      amount "Fade" 0-1 step0.01 default 0.4(褪色の強さ)
      variation "Variation" 0-1 step0.05 default 0.6
      (セルごとの褪色量のばらつき。0=全セル均一、1=ほぼ褪色しない
      セル〜強く褪色したセルまで混在)
- [ ] P4-3. セルごとの褪色量は決定論的疑似乱数で決める
      (SleeveGlossPlugin.hash01と同じsinハッシュ方式。
      再描画・再起動で同じセルは同じ褪色量)
- [ ] P4-4. 無効時、およびamount=0の時は修飾を積まず従来と同一
- [ ] P4-5. タップ再生・D&D・右クリックのヒット領域が変わらない

## P5. プラグイン「フチ・角の摩耗」id: edge-wear

対象ファイル: Records/EdgeWearPlugin.swift

- [ ] P5-1. jacketOverlay で、ジャケットのフチに沿った白っぽい
      擦り切れ(抜き差しで印刷が剥げた紙色)と、角のつぶれを重ねる。
      四辺の摩耗の強さは均等ではなくセルごとに偏りがあること
      (実物は特定の辺・角が特に削れる)
- [ ] P5-2. パラメータ(定義済み・変更しない):
      amount "Wear" 0-1 step0.01 default 0.35(フチの摩耗量)
      corners "Corner Wear" 0-1 step0.01 default 0.4(角の摩耗量)
- [ ] P5-3. 摩耗パターンはセルごとの決定論的疑似乱数
      (sinハッシュ方式)で変える。再描画でパターンが変わらないこと
- [ ] P5-4. amount≈0かつcorners≈0の実効強度ならオーバーレイを
      返さない(無効時と同じ描画構造)。allowsHitTesting(false)必須
      (角丸クリップは基盤側で適用済み)

## P6. プラグイン「黄変」id: yellowing

対象ファイル: Records/YellowingPlugin.swift

- [ ] P6-1. 白・淡色のジャケットが経年でアイボリー〜クリーム色に
      黄ばむ劣化を表現する。淡色部ほど強く効くこと
      (例: colorMultiplyで青チャンネルを抑制し、暗部への影響を抑える等)
- [ ] P6-2. パラメータ(定義済み・変更しない):
      intensity "Intensity" 0-1 step0.01 default 0.35(黄変の強さ)
      stains "Stains" 0-1 step0.01 default 0.3
      (局所的に濃く黄ばむシミの量。シミの位置・形・個数は
      セルごとの決定論的疑似乱数)
- [ ] P6-3. セルごとの黄変量・シミパターンは決定論的疑似乱数
      (sinハッシュ方式)でばらつかせる
- [ ] P6-4. 無効時、およびintensity=0の時は修飾を積まず従来と同一

## P7. プラグイン「リングウェア」id: ring-wear

対象ファイル: Records/RingWearPlugin.swift

- [ ] P7-1. jacketOverlay で、中身のレコード盤の形がジャケット表面に
      浮き出た円形のすり跡を描く。実物の特徴: 盤の外周に沿った
      うっすら明るい(または暗い)リング+リング内側のごく薄い
      色調差。半径は盤の直径に近い(セル一辺の85〜95%程度)
- [ ] P7-2. パラメータ(定義済み・変更しない):
      visibility "Visibility" 0-1 step0.01 default 0.5(リングの濃さ)
      frequency "Frequency" 0-1 step0.05 default 0.7
      (セルがリングウェアを持つ確率。ハッシュ値<frequencyの
      セルだけ描画し、残りはオーバーレイ無し)
- [ ] P7-3. リングの半径・円心のずれ・リングの太さ・濃さは
      セルごとの決定論的疑似乱数(sinハッシュ方式)でばらつかせる
- [ ] P7-4. 非該当セル・visibility≈0ではオーバーレイを返さない。
      allowsHitTesting(false)必須

## P8. プラグイン「スカッフ(擦りキズ)」id: scuffs

対象ファイル: Records/ScuffsPlugin.swift

- [ ] P8-1. jacketOverlay で、ジャケット表面の擦りキズを2種類描く:
      髪の毛状の細い淡い線傷(短い弧・直線状)と、白い斑点状の
      すり傷(小さな点群)。暗いジャケットで目立つ実物の見た目に
      近い、繊細で目立ちすぎない表現にすること
- [ ] P8-2. パラメータ(定義済み・変更しない):
      amount "Amount" 0-1 step0.01 default 0.4(傷の量・密度)
      style "Style" options(hairline / speckles / both、default both)
- [ ] P8-3. 傷の位置・向き・本数・長さはセルごとの決定論的疑似乱数
      (sinハッシュ方式)で生成し、再描画・再起動で変わらないこと
- [ ] P8-4. amount≈0ではオーバーレイを返さない。
      allowsHitTesting(false)必須
